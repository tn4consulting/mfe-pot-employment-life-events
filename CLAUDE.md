# mfe-pot-employment-life-events

## What this is

The **client-centric "you lost your job" guided journey** frontend for the mfe-pot Government of Canada MFE proof-of-technology — the app that stitches `mfe-pot-job-bank`, `mfe-pot-employment-insurance`, and `mfe-pot-dashboard` together into one narrative, rather than presenting them as separate benefit programs. Federated as a remote into `mfe-pot-shell`. Also embeds dashboard's payment-history widget directly (host-mediated via the shell — see the platform repo's CLAUDE.md "Federation" section). The fifth and final app extracted from the platform repo, and the second converted to React.

**This repo doesn't carry its own architecture doc.** Full rationale — bilingual/WCAG/GCDS requirements, the Native Federation setup, the federation-sharing policy, security model, i18n mechanism, hosting/Helm pattern, and every non-obvious gotcha behind the code in this repo — lives in **`../mfe-pot-platform/CLAUDE.md`**. Read it before making any architectural change here; this file only covers what's specific to this repo. See `../CLAUDE.md` (the `mfe-pot` meta repo) for the full 6-repo map.

## What's in this repo

- `apps/employment-life-events` — the only app; frontend-only, federated on port `4202` in local dev. No co-located BFF — there's no distinct bounded context here that justifies its own backend. `apps/employment-life-events/src/app/*.tsx` holds every component directly (`App.tsx`, `GuidedJourney.tsx`) — no separate `libs/<name>/feature-*` library the way this repo had before converting to React (see the platform repo's CLAUDE.md, "Components live in the app").
- `charts/employment-life-events` — depends only on the platform repo's `mfe-frontend-lib` (no BFF, so `mfe-backend-lib` isn't used), same shape as shell's chart.

Depends on published packages from GitHub Packages: `@tn4consulting/shared-auth`, `shared-content-client`, `shared-federation-config`, `shared-federation-runtime`, `shared-i18n`, `shared-locale-sync`, `shared-runtime-config` (pinned in `package.json`; keep in sync with `platform-versions.json` in `mfe-pot-platform`). **Deliberately does not depend on `@tn4consulting/shared-ui-scds-core`** (SCDS, the family's self-contained design system now that GCDS has been removed entirely — see the platform repo's CLAUDE.md) — confirmed genuinely unused (this app renders no `scds-*` element of its own, only the shell renders app-frame chrome, and this app's own components are unstyled beyond what it embeds from dashboard's federated `PaymentHistoryWidget`) and dropped rather than carried as dead weight.

## Repo-specific things worth knowing

- **`src/runtime-config.ts` and `public/env.js` were added specifically for `ContentClient`'s `strapiBaseUrl`** — this app previously had neither (no BFF of its own, nothing to configure), but now fetches a CMS-driven intro block (`employment-life-events.intro` key) the same way `mfe-pot-dashboard`/`mfe-pot-job-bank`/`mfe-pot-employment-insurance` do. `App.tsx` renders it above `GuidedJourney.tsx`, re-fetched via a `useEffect` on cross-remote locale change. `charts/employment-life-events/values.yaml`'s `frontend.runtimeConfig.strapiBaseUrl` points at `mfe-pot-platform`'s `charts/strapi` (`http://cms.mfe-pot.local`, browser-to-server, not in-cluster Service DNS).
- **A real, pre-existing production bug found while this app was still Angular, fixed as part of wiring up the CMS content above**: the old `feature-guided-journey` lib imported `TranslocoPipe` directly for its own chrome text, in addition to `App`'s own import of the same package — two separate compilation units both importing Transloco tripped a real `NG0201`/`NG0912` crash (confirmed live, whole page blank for any signed-in citizen). Fixed at the time by having the feature component take its translated strings as plain `@Input()`s from `App` instead of importing Transloco itself. **This bug class doesn't exist anymore, and won't recur** — now that this app is React, `GuidedJourney.tsx` and `App.tsx` share the exact same `useTranslations()` hook call site conceptually (props passed down, same as the Angular-era fix), and React has no per-bundle DI-singleton-identity concept for two compilation units' imports to collide over in the first place. Kept here as a one-line historical note, not active guidance.
- **`usePaymentHistoryWidgetLoader()` (from `@tn4consulting/shared-federation-runtime`) is called in `apps/employment-life-events/src/app/GuidedJourney.tsx`** — this is the host-mediated widget-composition pattern the platform repo's CLAUDE.md describes ("Cross-remote widget composition is host-mediated, not remote-to-remote"): the shell loads dashboard's `./PaymentHistoryWidget` and hands the resolved component down through this Context. This app never imports dashboard directly, federated or otherwise — a plain nested `loadRemoteModule` call from here would hang forever with no error. If this stops working, check the shell repo's wiring (`apps/shell/src/app/routes.tsx`) before assuming the bug is here — and specifically check whether shell's own `build.mjs`/`serve.mjs` correctly marks `@tn4consulting/shared-federation-runtime` as `external` in its non-federation-managed entry bundle, a real bug found and fixed once (see `mfe-pot-shell`'s own CLAUDE.md and commit history) that silently degrades this exact widget to its "unavailable" fallback with no console error.
- **CI** (`.github/workflows/ci.yml`): lint/test/build, then builds the image, spins up an ephemeral `kind` cluster, `helm install`s this chart, and curls the Ingress-routed hostname to confirm it serves. See `README.md` for local install/serve/build/Docker/Helm instructions.

## Renovate

`renovate.json` extends `github>tn4consulting/mfe-pot-platform` — the shared preset (groups `react`, `react-dom`, and `@tn4consulting/shared-ui-scds-core` into one coordinated pinned bump, the federation-shared singletons — though this repo doesn't itself depend on the SCDS package, per the note above). Don't hand-roll React/SCDS version bumps here independently of the other 5 repos; `platform-versions.json` in `mfe-pot-platform` is the source of truth for what version they should all be on.
